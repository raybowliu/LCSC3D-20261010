# KiCad 追加功能验证记录

验证日期：2026-10-31。本次为本地开发交付，应用版本沿用工作区的 2.4.42。

## 功能范围

- KiCad 的 Lib 区增加“追加”，与“合并”互斥，复用 AD 的追加配置页面和工程导入按钮。
- 选择已有 `.kicad_sym`、`.pretty` 或两者，只追加对应格式；只指定 `.kicad_pro` 时生成工程配套库，支持分别设置库目录、库名、3D 目录和独立器件目录。
- 同名旧符号保留原内容；相同封装复用，同名不同封装加序号，新符号引用最终封装名称。已有条目、模型、附加文件、注释及库表自定义内容保留。
- 配置页可直接将当前填写的库注册到工程的 `sym-lib-table` / `fp-lib-table`，不依赖下载列表或先保存配置。同名昵称指向其他库时报告冲突。已有库下载期间不自动导入；仅指定工程时自动注册本次成功生成的集中库。
- AD 与 KiCad 的模式、目标和配置分别保存。追加期间主页保存目录锁定，退出追加恢复普通导出设置。
- 修改已有符号库、工程库表前使用现有自动备份和恢复管理。写入失败恢复本次库修改；停止下载撤销整批输出。外部修改保留，恢复失败时在应用数据目录保留恢复资料。

## 空工程导入失败修复（2026-10-31）

用户最初选择的 `demo.kicad_pro` 只有两个字节，内容为 `{}`。日志显示导入在 `read_project()` 的 `meta` 字段校验处失败。KiCad 创建工程时，在不能复制模板的情况下会生成空 JSON 对象；库引用实际保存在独立的工程库表中。原实现把 `meta` 当作必填字段，导致有效的最小工程被拒绝。此前验证样例均预置了 `meta`，没有覆盖这种情况。

修复允许工程 JSON 对象不含 `meta`；字段存在时仍检查其类型，继续拒绝损坏 JSON、无效编码和非对象根节点。导入只更新 `sym-lib-table` / `fp-lib-table`，保留工程原始字节与已有库内容。原有防止并发修改、备份和回滚的处理继续使用。

- 新回归在修复前复现了四种不含 `meta` 的工程被拒绝；修复后追加专项 17 项测试全部通过。覆盖 `{}`、换行、UTF-8 BOM、自定义字段、三种格式的仅工程下载、重复导入，以及 14 种无效工程输入。
- 本次重新完整执行全量单元测试，875 项全部通过。覆盖配置页保存和空工程直接导入、既有 AD / KiCad 功能、日志打包、清除后继续写日志和崩溃捕获；测试使用隔离的 `LOCALAPPDATA`。
- 使用用户实际 `demo.kicad_sym` 和 `demo.pretty` 的副本，对两个字节的空工程、KiCad 安装模板和 GUI 保存后的工程分别验证：首次新增两类库，再次导入跳过两类库；17 个库文件及工程原始内容保持不变。没有修改用户原工程或原库。
- KiCad 10.0.3 CLI 成功读取并绘制用户库副本中的 23 个符号单元和 16 个封装。这项验证覆盖库文件解析和绘制，没有通过 GUI 放置器件。
- 新增诊断回归确认无效工程导入会记录错误编号、异常类型及 `read_project()` 调用位置；更正为空工程后可继续成功导入。
- 重新构建并更新 `outputs/LCSC3D.exe`，18 组离线实际窗口验证全部通过。其中已有库直接导入和仅指定工程下载使用 `{}` 工程，并校验工程原始字节保持不变；导入页面截图显示新增两份库成功。KiCad 10.0.3 CLI 也成功读取新 EXE 产生的追加库。
